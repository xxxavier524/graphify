# 实施方案：股票直播课 → 个人交易 Skill 蒸馏（v2）

> 基于原计划书（《股票直播课 → 个人交易 Skill 蒸馏》）的背景与约束，结合可行性评审结论修订而成。
> 目标环境：Mac mini M4 / 16G 内存，全程本地、免费优先，仅在收益明显处可选用少量 Claude API。

---

## 一、背景与目标（承接原计划书）

- **输入**：100+ 条盘中直播视频，单条 5 小时以上，总量约 500+ 小时；语音讲解为主，K 线画面不做图像识别。
- **特点**：知识点稀疏、信噪比低（大量等待、闲聊、重复）；个股名/术语易转错。
- **三件产物**：
  1. **模式 A**：带准确时间戳的句级逐字稿（SRT + JSONL），用于全文检索和回放对照 K 线；
  2. **模式 B**：按主题归类的知识卡片，每条挂「视频 + 时间戳」回链；
  3. **个人 Skill**：复刻讲师的**交易体系**（选股、买卖点、仓位风控、盘面信号）+ **心态提醒**（回撤焦虑、追高冲动、止损执行、扛单/卖飞）。
- **硬约束**：时间轴必须准；完整性必须有保证；准确率"可用即可"；16G 内存；免费优先。

### 相对 v1 的关键修订

| # | 修订点 | 原因 |
|---|---|---|
| 1 | 新增 **②′ 完整性校验** 阶段（覆盖率脚本） | VAD 在背景音乐/低音量段可能整段丢句，"完整性保证"不能靠肉眼 |
| 2 | 阶段④前新增**零成本规则预过滤** | 本地 7B 级模型吞吐有限，先用规则砍掉 50–70% 闲聊，LLM 机时从"数天"降到"1–2 晚" |
| 3 | 术语校正改为**白名单制**：只有词典确定性替换落盘，LLM 仅产出候选清单供人工入典 | 小模型上下文纠错可能把对的改错，引入不可审计的新错误 |
| 4 | 补齐**阶段④⑤的 LLM 机时估算**与**磁盘估算** | v1 只估了转录机时；500h WAV ≈ 58GB，需要管道/即删策略 |
| 5 | 时间戳策略明确为**句级（VAD 段边界）**，不依赖字级 | SenseVoice 字级时间戳有已知的对不齐问题（FunASR #2324、SenseVoice #215） |
| 6 | 每个里程碑增加**可量化验收标准** | "跑通"不可验收，时间戳漂移和覆盖率必须在 PoC 阶段量化确认 |

## 二、总体架构（七阶段流水线）

```
视频 ──①抽音频(ffmpeg, 管道/即删)──▶ 16k单声道音频
音频 ──②转录(SenseVoice+VAD, 句级时间戳)──▶ transcript/*.jsonl + *.srt   ← 模式A
     ──②′完整性校验(覆盖率/漂移/单调性)──▶ qa/coverage_report.csv
字幕 ──③术语校正(词典确定性替换；LLM仅出候选)──▶ clean/*.jsonl + glossary.csv
字幕 ──④a 规则预过滤(关键词密度/语速)──▶ 候选段落(砍掉50–70%)
     ──④b 本地LLM打分分类──▶ signal/*.jsonl(干货段落)
干货 ──⑤蒸馏(分桶→LLM归并成卡片, 挂时间戳回链)──▶ knowledge/**/*.md   ← 模式B
卡片 ──⑥组装(Claude精修)──▶ skill/SKILL.md + references/              ← 个人Skill
```

| 阶段 | 工具 | 产物 | 可挂机 |
|---|---|---|---|
| ① 抽音频 | ffmpeg | 临时 wav（转完即删）或管道直喂 | ✅ |
| ② 转录 | funasr（SenseVoiceSmall + fsmn-vad） | `transcript/*.jsonl` + `*.srt` | ✅ |
| ②′ 校验 | 自写脚本 | `qa/coverage_report.csv` | ✅ |
| ③ 校正 | 脚本 + glossary.csv（LLM 仅出候选） | `clean/*.jsonl` | ✅ |
| ④ 挑干货 | 规则脚本 + 本地 Qwen（ollama/llama.cpp） | `signal/*.jsonl` | ✅ |
| ⑤ 蒸馏 | 本地 LLM（质量不够时换 Claude Haiku 批量） | `knowledge/**/*.md` | ✅ |
| ⑥ 组装 | Claude | `skill/SKILL.md` + `references/` | 人工参与 |

所有批处理阶段以**视频为最小重试单元**，每个视频处理完写 `.done` 标记文件，脚本启动时跳过已完成项——断点续跑、幂等。

## 三、技术选型与决策理由

### 3.1 转录引擎：funasr（PoC 与默认）→ 可选 MLX/SenseVoice.cpp（提速）

- **PoC 与默认走 funasr**（官方 Python 包）：一行 `AutoModel` 集成 SenseVoiceSmall + fsmn-vad + 标点，开发成本最低，时间戳行为可控。M4 CPU 上 SenseVoice 非自回归推理约 30–50× 实时，500h ≈ **10–17 小时机时**，几晚挂机足够。
- **嫌慢再换**：MLX 实现（GPU 加速，M4 Pro 实测 27 分钟音频 14 秒）或 `SenseVoice.cpp`（ggml 量化）。生态较糙，放量阶段按需切换，接口产物格式不变。
- **Whisper 系仅作对照**：whisper-large-v3-turbo 在 M4 约 6–8× 实时，500h 要 60–80 小时，且中文直播口语不占优，不作主力。
- **Paraformer 留作精修备选**：中文字准更高、原生热词强，但 Mac 上只能 CPU 跑 PyTorch、慢；只对个别高价值视频用。

### 3.2 时间戳策略（命门，单独说明）

- **只信句级时间戳**：以 VAD 段边界为准生成 SRT，这条链路可靠，满足"回放对照 K 线"。
- **不依赖字级时间戳**：SenseVoice 的 CTC 字级对齐有字符数与时间戳数不匹配的已知 issue，不进入产物。
- **PoC 验收点**：对一条完整 5 小时视频，人工抽查**最后 10 分钟**的 5 个时间点，与播放器对照，误差需 < 2 秒（防长音频累计漂移）。

### 3.3 本地 LLM：Qwen3-8B Q4（默认）

- 16G 内存的现实选择：8B Q4 约 5GB，留足系统与转录进程余量；14B Q4 约 9GB，仅在 8B 质量不够且独占机器时用。
- 运行时：ollama（省心）或 llama.cpp server（可控并发）。
- 打分/分类这类**封闭式判断**8B 可胜任；**开放式蒸馏**（⑤）若抽查质量不行，改用 Claude Haiku 批量——经④过滤后送审文本量已不大，成本可控，不必死守全免费。

### 3.4 术语词典

- 打底：用 akshare/efinance 拉一份全 A 股股票名称+代码表，生成常见误转变体（同音字）。
- 自举：阶段二集中扫错词入典；之后持续补充。
- 格式 `glossary.csv`：`wrong,right,type,note`（type: 股名/术语/口头禅）。

## 四、各阶段详细设计

### ① 抽音频

```bash
ffmpeg -i raw/037.mp4 -vn -ac 1 -ar 16000 -f wav audio/037.wav
# 磁盘紧张时：转录完成后立即删除 wav，或直接以管道喂给转录脚本
```

### ② 转录（核心脚本骨架）

```python
from funasr import AutoModel

model = AutoModel(
    model="iic/SenseVoiceSmall",
    vad_model="fsmn-vad",
    vad_kwargs={"max_single_segment_time": 30000},  # 30s 上限，时间戳粒度足够细
)
res = model.generate(input=wav_path, language="zh", use_itn=True, batch_size_s=300)
# 以 VAD 段边界落 JSONL：{video_id, seg_id, start_ms, end_ms, text}
# 再由 JSONL 派生 SRT（模式A 的两种载体，JSONL 给机器、SRT 给播放器）
```

每条视频产出后写 `transcript/.done/<video_id>`，主循环跳过已完成项。

### ②′ 完整性校验

对每条视频计算并写入 `qa/coverage_report.csv`：

1. **覆盖率** = 字幕段总时长 ÷ VAD 检出语音总时长，**阈值 ≥ 0.95**，低于阈值标红重跑/人工查；
2. **时间戳单调性**：start 严格递增、无负长段；
3. **尾部漂移抽查清单**：自动从每条视频末 10 分钟抽 3 句生成"待人工对照"列表（只在 PoC 和每批次抽样做）。

### ③ 术语校正（白名单制）

- **Pass 1（落盘）**：仅按 `glossary.csv` 做确定性查找替换，产出 `clean/*.jsonl`，并记录替换日志（可审计、可回滚）。
- **Pass 2（不落盘）**：本地 LLM 扫描疑似错词（股名上下文不通、低频怪词），输出**候选清单** `qa/term_candidates.csv`，人工审核通过后才入典、下批生效。LLM 永不直接改稿。

### ④ 挑干货

**④a 规则预过滤（零成本，目标砍掉 50–70%）**

- 把相邻句聚合成 2–5 分钟窗口；
- 特征：交易关键词命中密度（买点/卖点/止损/仓位/均线/分时/缩量/题材/龙头…）、字符密度（语速，等待时段语速低）、窗口内沉默占比；
- 低于阈值的窗口直接弃，阈值在阶段二用 5–10 条视频标定。

**④b 本地 LLM 打分（结构化输出）**

```
输入：候选窗口文本
输出 JSON：{
  "score": 0-5,            # 干货密度
  "labels": ["体系-买卖点" | "体系-仓位风控" | "体系-盘面信号" | "体系-选股" |
             "心态" | "个股点评" | "闲聊"],
  "summary": "一句话概括"
}
```

`score ≥ 3` 保留进 `signal/*.jsonl`：`{video_id, start_ms, end_ms, score, labels, summary, text}`。
阶段二人工抽 50 个窗口对照 LLM 打分，校准提示词后再放量。

### ⑤ 蒸馏成知识卡片

1. **分桶**：按 labels + 关键词把干货段落归到主题桶（买卖点/仓位/盘面信号/选股/心态-追高/心态-止损/…）；
2. **归并**：每桶内 LLM 把多个段落归并为去重的知识卡片，**讲师多次重复的规则正是高置信信号**，归并时保留"出现次数"；
3. **卡片模板**（`knowledge/system/*.md`、`knowledge/mindset/*.md`）：

```markdown
## 卡片标题（一条可执行的规则）
- 主线: 交易体系 | 心态提醒
- 主题: 买卖点 / 仓位 / ...
- 规则: （讲师原话提炼，保留口语中的限定条件）
- 适用场景 / 反例: ...
- 置信度: 出现 N 次
- 出处: [视频037 01:23:45](../transcript/037.srt) · [视频082 03:10:20](../transcript/082.srt)
```

回链格式统一为 `视频ID + hh:mm:ss`，便于在播放器中手动定位对照 K 线。

### ⑥ 组装 Skill

- **SKILL.md 控制在 500 行内**，采用渐进披露：主文件只放体系骨架、决策流程和触发规则，细则放 `references/`。
- **结构**：

```
skill/
├── SKILL.md                    # 何时用、体系总览、分析流程、心态触发规则
└── references/
    ├── system-entry-exit.md    # 买卖点细则
    ├── system-position.md      # 仓位与风控
    ├── system-signals.md       # 盘面信号判断
    ├── system-selection.md     # 选股逻辑
    └── mindset-triggers.md     # 情绪场景 → 纪律提醒对照表
```

- **心态提醒必须写显式触发条件**，否则 Claude 不会自发触发。SKILL.md 中明确：

```markdown
## 心态提醒触发规则
当用户对话中出现以下信号时，先查 references/mindset-triggers.md 给出对应纪律提醒，再继续分析：
- 追高冲动：「现在追还来得及吗」「要起飞了」「满仓干」
- 止损犹豫：「再等等会不会回来」「要不要割」「被套了」
- 扛单/卖飞情绪：「早知道」「卖飞了」「不甘心」
- 回撤焦虑：「亏麻了」「天天跌」「要不要清仓」
```

- 组装这一步用 Claude（交互式），人工对体系两条主线做最终取舍。
- SKILL.md 中加入一句定位声明：本 Skill 是对特定讲师课程体系的整理复刻，输出为该体系下的分析框架与纪律提醒，不构成投资建议。

## 五、资源估算（修订版，含 LLM 阶段）

| 项目 | 估算 | 说明 |
|---|---|---|
| 转录机时 | **10–17 小时**（funasr CPU）；MLX 可压到 1–2 小时级 | 500h ÷ 30–50× 实时；2–3 晚挂机 |
| 文本量 | 转写约 **450–600 万字** ≈ 600–900 万 token | 中文直播均速估 150–200 字/分钟 |
| ④b LLM 机时 | **1–2 晚**（约 6–15 小时） | 预过滤后约 30–50% 文本送 LLM；8B Q4 在 M4 上 prefill 数百 token/s |
| ⑤ LLM 机时 | 数小时 | ④ 过滤后干货量已小一个量级 |
| 磁盘 | wav 峰值 **< 5GB**（即转即删）；字幕全量 < 100MB | 500h 全量 wav 是 58GB，靠即删策略避开；视频本体另计 |
| 人工 | 词典自举几小时 + 每里程碑抽查 1–2 小时 + Skill 终审半天 | 集中在阶段二、四 |

## 七、里程碑与验收标准

| 里程碑 | 范围 | 验收标准（量化） |
|---|---|---|
| **M1 · 打通** | 1 条完整 5h 视频跑 ①→⑥ | ① 末 10 分钟抽 5 点时间戳误差 < 2s；② 覆盖率 ≥ 95%；③ 蒸馏出 ≥ 5 张可读卡片且回链可定位 |
| **M2 · 建词典** | 5–10 条 | glossary ≥ 200 条；抽 50 窗口 LLM 打分与人工判断一致率 ≥ 80%；预过滤阈值标定完成 |
| **M3 · 全量转录** | 100+ 条 | coverage_report 无红项（或红项均人工确认）；失败重跑清单清零 |
| **M4 · 蒸馏组装** | 全量 | 模式B 卡片体系/心态两线齐备；SKILL.md < 500 行；人工终审通过 |
| **M5 · 验证迭代** | — | 3 个新标的按体系走通分析流程；3 个情绪场景能正确触发心态提醒 |

任何里程碑验收不过，先回修该阶段再继续——**不带病放量**。

## 八、风险与对策

| 风险 | 对策 |
|---|---|
| 长音频时间戳累计漂移 | M1 强制验收末段误差；只用 VAD 句级时间戳，不碰字级 |
| VAD 丢段导致内容缺失 | ②′ 覆盖率脚本硬性把关（≥95%），缺口自动报告 |
| 股名/术语转错 | 股票名称表打底 + 白名单词典替换 + 候选人工入典；高价值视频 Paraformer 精修 |
| 本地 7B 打分质量不稳 | 规则预过滤兜底完整性（漏判只发生在已被规则判为低密度的窗口）；M2 一致率校准；不达标升级 14B 或 Claude Haiku |
| LLM 纠错引入新错误 | LLM 永不直接改稿，只出候选清单 |
| 16G 内存吃紧 | 转录与 LLM 阶段分时跑，不并行；模型选 8B Q4 |
| 磁盘不足 | 音频即转即删，峰值 < 5GB |
| 全量跑完才发现问题 | M1 端到端 PoC + 每里程碑量化验收 |
